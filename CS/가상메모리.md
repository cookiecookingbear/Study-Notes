# 가상 메모리(Virtual Memory)

- 프로세스에게 실제 램보다 훨씬 큰 연속적인 메모리가 있는 것처럼 보이게 하는 메모리 관리 기법

- 프로세스가 사용하는 주소(가상 주소, Virtual Address)와 실제 메모리 주소(Physical Address)를 분리하는 기술

- 프로세스 A와 프로세스 B가 있다고 할 때, 

	1. A와 B 모두 CPU에서는 0x1000라는 주소범위를 사용한다. 이를 ==가상 주소==라고 한다.

        > 가상 주소는 CPU가 생성하고, 프로세스와 CPU가 사용하는 주소다.

	1. 이런 가상 주소를 실제 메모리에 접근할 때는 MMU(Memory Management Unit)이 ==물리 주소==로 변환하여 접근한다.

- 가상 메모리는 고정된 크기의 블록으로 관리되는데, 이를 [페이지(Page)](./CS/가상메모리_페이징.md)라고 한다.

	> 보통 4kb가 많이 사용된다.

- 페이지가 가상 메모리의 단위라고 한다면, 실제 메모리의 단위는 프레임(Frame)이라고 한다.

- 가상 주소를 물리 주소로 변환하려면 매핑 정보가 필요한데, 이 매핑 정보를 정리한 표를 Page Table이라고 한다.

- 가상 메모리의 장점

	1. 프로세스 내에서 동일값의 주소 사용 가능(운영체제 선에서 다른 물리 주소에 연결된다)
	1. 실제 램은 빈 공간이 조각난다. 하지만 프로세스 입장에서는 연속된 공간처럼 보이게 사용이 가능하다.
	1. 실제 램의 용량보다 더 큰 프로그램 실행이 가능하다.

    	> 시스템의 메모리 용량보다 실행하는 프로그램의 메모리 요구량이 크다면, 프로그램에서 요구하는 메모리 요구량을 전부 램에 탑재하는 것이 아니라, **필요한 내용만** 램에 탑재하고, 나머지는 SSD나 HDD등 보조기억장치에 둔다.\
		> 이를[Demand Paging](./CS/가상메모리_디맨드페이징.md)이라고 한다.

- TLB(Translation Lookaside Buffer)

	- 매번 페이지 테이블을 조회하면 속도가 느려진다. 이를 해결하기 위해 TLB가 최근 주소를 변환한 결과를 캐싱한다.

    	> 가상 주소 -> TLB확인 -> 있으면 바로 변환, 없으면 Page Table확인

- RAM 용량이 부족하고, Page Fault가 발생하면, 운영체제는 페이지를 교체한다. Page Fault가 너무 많이 발생하면 CPU는 실제로 계산을 수행하지 않고 페이지 교체만 수행하는데, 이 상태를 [Thrashing](./CS/Thrashing.md)이라고 한다.
