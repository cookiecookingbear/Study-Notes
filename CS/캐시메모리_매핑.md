# 캐시메모리 매핑

- 주기억장치의 블록을 캐시의 어느 위치에 저장할 것인지 결정하는 방식이다.

- CPU가 특정 메모리 주소에 접근하려고 할 때, 

	1. 이 데이터가 캐시에 있는가?
	1. 있다면 캐시의 어디에 있는가?
	1. 없다면 RAM에서 가져온 데이터를 캐시 어디에 넣을 것인가?

	를 판단해야 한다.

### 방식

1. 직접 매핑(Direct Mapping)

    > 메모리 블록이 들어갈 캐시 위치가 하나로 고정

	- 주소 구조 : `Tag` `Index` `Offset`

        > Tag : 실제 어떤 메모리 블록인지 구분\
		> Index  : 캐시의 어느 라인을 볼지 구분\
		> Offset : 캐시 라인 내부에서 몇 번째 바이트인지 결정
		
	- 접근 과정

        1. 주소의 Index로 Cache Line 선택
        1. 선택된 Line의 Tag와 주소의 Tag비교
        1. Tag가 같고 Valid Bit가 1이면 Hit
        1. 아니면 Miss

            > Valid Bit : 캐시 라인이 현재 유효한 데이터를 가지고 있는지 표시한다.
			>> 0이면 비어 있거나 무효\
			>> 1이면 유효한 데이터 있음

     - Replacemet Policy

        - 라인이 들어갈 자리가 고정되어 있기 때문에 선택지가 없음.

	- 장점

        1. 구현이 단순
        1. 검색이 빠름
        1. 하드웨어 비용이 낮음

    - 단점

        1. 충돌 Miss가 많이 발생할 수 있음

            > 예를 들어, 블록 A와 블록 B가 캐시 라인 C에만 들어가야 하는데, A와 B를 번갈아가며 호출해야 한다면, 항상 Miss가 난다.\
            > 이런 현상을 ==Cache Conflict(캐시 충돌)== 이라고 한다.

1. 완전 연관 매핑(Fully Associative Mapping)

    > 메모리 블록이 캐시 어디든 들어갈 수 있음

    - 주소 구조 : `Tag` `Offset`

        > 직접 매핑과 다르게 Index가 없다.

    - 접근 과정

        1. 캐시의 모든 Line을 검사
        1. 각 Line의 Tag와 요청 주소의 Tag비교
        1. 일치하는 Line이 있으면 Hit
        1. 없으면 Miss

    - Replacemet Policy

        - 라인이 아무데나 들어갈 수 있기 때문에 LRU, FIFO, Random, Clock계열의 알고리즘을 통해 선택한다.

    - 장점

        1. 충돌 Miss가 가장 적음
        1. 캐시 공간 활용이 유연함

    - 단점

        1. 하드웨어 비용이 큼
        1. 모든 Line의 Tag를 동시에 비교해야 함
        1. 검색 구조가 복잡함

1. 집합 연관 매핑(Set Associative Mapping)

	> 정해진 집합 안의 여러 위치 중 하나에 들어감

    - N-way Set Associative

        > 하나의 세트 안에 N개의 캐시 라인이 있다는 뜻\

        > 만약 캐시 라인이 총 8개인데, 2-way라면 세트 하나에 라인이 두개씩 들어간다.

    - 매핑 방식

        > 예를 들어 4개의 세트가 있다고 할 때, 각 블럭은 순서대로 세트 안에 들어가야 하지만, 해당 세트의 어디에 들어갈지는 상관 없다.
        >> Block0 : Set0 확정, Line0에 들어갈지 Line1에 들어갈지는 자유.

    - 주소 구조 : `Tag` `Set Index` `Offset`
    
    - 접근 과정

        1. 주소의 Set Index로 Set 선택
        1. 해당 Set 안의 모든 Line의 Tag 비교
        1. 일치하면 Hit
        1. 없으면 Miss

        > 2-way라면 Line 2개만 비교, 4-way라면 Line 4개 비교

     - Replacemet Policy

        - 라인이 들어갈 자리가 Set내에서는 자유이기 때문에 완전 연관 매핑과 같이 LRU, FIFO, Random, Clock계열의 알고리즘을 통해 교체한다.

    - 장점

        1. 직접 매핑보다 충돌 Miss 감소
        1. 완전 연관보다 하드웨어 비용 낮음
        1. 실제 CPU 캐시에서 많이 사용

    - 단점

        1. 직접 매핑보다 복잡하다.
        1. Set 내부에서 교체 대상 선택 필요
        1. Way 수가 커질수록 비교 회로 증가
