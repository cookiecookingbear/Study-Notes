# PCB와 PC

### PC를 별도로 저장하는 이유

- 컨텍스트 스위칭을 할 때, 프로세스 A의 PC값을 어딘가 저장해두지 않으면 프로세스 B로 전환할 때, A의 진행 상황을 완전히 잃어버리기 때문에 PCB안에 PC값을 별도로 저장한다.

### 컨텍스트 스위칭과 PCB

- PC는 해당 프로세스가 다음에 실행할 명령어의 주소만 알려줄 뿐이고, 그때까지 계산했던 값들은 알려주지 않는다. 이런 이유로 PCB가 필요하다.

- PCB(TCB)에는 아래의 값들이 통째로 저장된다. 이 값들을 **컨텍스트**라고 부른다.

    1. PC
    1. 범용 레지스터
        - 중간 계산 값
    1. Stack Pointer
        - 현재 스택의 꼭대기 위치
    1. Flag/Status Register
        - 비교 연산 결과 등
    1. Base Pointer
        - 현재 스택 프레임 기준점

### PCB와 [TCB](TCB_threadControlBlock.md)

- 엄밀히 말하면, 위의 내용들은 PCB가 아니라 TCB에 저장된다.

- 실행 흐름의 단위는 프로세스가 아닌 스레드이고 만약 하나의 프로세스 안에 3개의 스레드가 있다면, 그 3개의 스레드는 각각 서로 다른 코드 위치를 실행하고 있으며 따라서 PC값도 3개가 각각 필요하다.

- 실제로는:

    - PCB : 프로세스 전체가 공유하는 정보
        > PID, 메모리 맵, 열린 파일 목록, 권한 등을 저장
    - TCB : 스레드별로 다른 정보
        > PC, 레지스터 값, 스택 포인터, 스레드 상태 등 위에서 언급된 정보들

- 여태 PC는 PCB에 저장된다는 맥락은, 교과서적으로 '단일 스레드 프로세스'를 전제로 한 단순화된 모델의 경우의 설명이다.

- 멀티스레드 환경이라면 PC는 TCB에 저장된다는 설명이 가장 정확하다.
