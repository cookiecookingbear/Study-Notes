# PC_예상질문

- Program Counter란 무엇인가요?
    > PC는 CPU가 다음에 실행할 명령어의 메모리 주소를 저장하는 레지스터입니다. 단순한 주소 저장을 넘어, 프로그램의 실행 흐름을 결정하는 역할을 합니다.

- PC가 없다면 어떤 문제가 발생하나요?

- PC와 MAR의 차이는 무엇인가요?
    > PC는 다음에 실행할 명령어의 주소만을 담는 전용 레지스터이고, MAR은 명령어든 데이터든 현재 메모리에 접근하기 위한 주소를 담는 범용 레지스터입니다. 인출 단계에서 PC 값이 MAR로 복사되기 때문에 그 순간에는 두 값이 같아집니다.

- PC와 IR의 차이는 무엇인가요?

- 인출(Fetch) 사이클에서 PC는 어떤 순서로 사용되나요?

- PC는 명령어 실행이 끝난 뒤에 증가하나요, 인출 직후에 증가하나요? 그 이유는 무엇인가요?

- PC의 증가 폭은 항상 일정한가요?
    > 고정 길이 명령어를 사용하는 RISC 계열에서는 항상 일정하지만, 가변 길이 명령어를 사용하는 x86 계열에서는 방금 인출한 명령어의 실제 길이만큼 증가합니다.

- PC 값이 순차적으로 증가하지 않는 경우는 어떤 상황들이 있나요?

- if문이나 for문 같은 제어문은 기계어 수준에서 어떻게 구현되나요?

- 조건 분기에서 Flag Register는 어떤 역할을 하나요?

- 함수를 호출할 때 PC와 스택에서는 각각 어떤 일이 일어나나요?

- 함수에서 반환할 때 실행 흐름이 원래 자리로 돌아올 수 있는 이유는 무엇인가요?

- 재귀 호출이 깊어지면 스택 오버플로우가 발생하는 이유를 PC와 연관지어 설명해 주세요.

- 버퍼 오버플로우 공격이 실행 흐름을 탈취할 수 있는 원리는 무엇인가요?

- 인터럽트가 발생했을 때 PC는 어떻게 처리되나요?

- 인터럽트 처리가 끝난 후 원래 실행하던 위치로 돌아올 수 있는 이유는 무엇인가요?

- PC의 비트 수는 무엇을 결정하나요?

- PC에 담기는 주소는 물리 주소인가요, 가상 주소인가요?

- CPU 코어에는 PC가 하나뿐인데, 어떻게 여러 프로세스가 동시에 실행될 수 있나요?

- PC 값은 컨텍스트 스위칭 시 어디에 저장되나요?

- 하나의 프로세스에 여러 스레드가 있을 때, PC는 몇 개가 필요한가요? 그 이유는 무엇인가요?

- 스레드들이 코드·데이터·힙 영역은 공유하면서도 PC와 스택은 각자 갖는 이유는 무엇인가요?

- PC에 임의의 값을 직접 대입할 수 있나요?
    > x86의 RIP처럼 대부분의 아키텍처에서는 mov 등으로 직접 대입할 수 없고, jmp·call·ret 같은 제어 흐름 명령어를 통해서만 변경할 수 있습니다. 실행 흐름이 임의의 위치로 이동하는 것을 막아 안정성과 보안을 확보하기 위함입니다.
