# .lib

## '미리 컴파일된 코드의 묶음' 혹은, '.dll을 연결해주는 역할'

- 내가 직접 소스코드를 작성하지 않아도 다른 사람이 만든 기능을 가져다 쓸 수 있게 만든 파일
- C#보다는 C++에서 많이 등장한다.
- 어떤 기능을 구현한 쪽에서 내부 구현은 밝히지 않으면서, 이 기능을 다른 곳에서 사용할 수 있게 하고 싶다면, 컴파일하여 .lib의 형태로 배포한다.

## 역할

1. **정적 라이브러리**

- 프로그램을 빌드 할 때, .lib이 같이 있으면 라이브러리 코드가 .exe안에 복사된다.
    > 링커는 정적 라이브러리에서 미해결 심벌을 해결하는 데 필요한 목적 파일 멤버를 선택하여 최종 결과물(실행 파일)에 결합한다.\
    > 이후 사용되지 않는 정보는 추가 최적화 과정에서 제거될 수도 있고, 그냥 라이브러리 전체를 강제로 포함시킬 수도 있다.(링커 옵션에 따라 다름)

- 연결된 exe이 있으면 실행 가능하고, 배포가 편하다는 장점이 있다.
- 단, exe안에 포함되므로 실행 파일의 크기가 증가한다.

2. **DLL Import Library**

- .dll파일을 만들면, 보통 `파일명.dll`, `파일명.lib`, `파일명.h`가 같이 만들어지는데, 헤더 파일은 함수와 타입의 선언을 제공하고, .dll파일은 함수의 실제 구현을 제공하고, .lib파일은 링커에 dll파일이 제공하는 심벌과 연결 정보를 제공한다.
- 정리하면, .lib파일은 `.dll파일이 내보내는 심벌 정보`, `임포트 테이블을 구성하기 위한 정보`, `호출을 간접 연결하기 위한 작은 스텁 또는 썽크`를 포함한다.
- 윈도우 OS에 한해서, 만약 .dll파일과 .lib파일이 같이 있다면 이때 .lib파일은 이미 컴파일된 코드의 묶음이 아니라, 실행파일에 .dll을 연결하기 위한 지표가 된다.

- 단, .dll이 항상 .lib을 필요로 하는 것은 아니다. 
    > Windows에서는 dll을 실행 중에 명시적으로 로드할 수 있다.

## 헤더와 .lib

- 헤더는 컴파일러가 함수, 클래스, 구조체 등의 선언과 타입 정보를 알 수 있도록 한다.
- 정적 `.lib`는 실제 구현이 담긴 목적 파일을 포함할 수 있다.
- 임포트 `.lib`는 실제 구현이 들어 있는 DLL을 링크하기 위한 정보를 제공한다.
- 헤더만 있고 필요한 `.lib`나 구현이 없다면 컴파일은 성공하더라도 미해결 외부 심벌로 인해 링크에 실패할 수 있다.

## 호환성

- `.lib`를 사용하려면 CPU 아키텍처, 호출 규약, 이름 맹글링, 객체 배치, 컴파일러 ABI, 런타임 라이브러리 설정 등이 호환되어야 한다.
- 소스 코드를 제공하지 않고 바이너리 형태로 기능을 배포할 수 있지만, 역공학을 완전히 방지하는 것은 아니다.

## C#과의 관계

- C#에서는 일반적으로 `.lib` 대신 CIL과 타입 메타데이터를 담은 .NET 어셈블리 `.dll`을 참조한다.
- C#에서 네이티브 DLL을 호출할 때도 일반적으로 P/Invoke를 사용하므로 임포트 `.lib`를 직접 참조하지 않는다.
- `.lib`는 C++ 언어 자체의 파일 형식이라기보다 네이티브 Windows 도구 체인에서 주로 사용하는 파일 형식이다.

#### 정리

- .cpp를 컴파일하면 .obj가 된다.
- .obj 여러개를 묶어 놓으면 .lib이 된다.
- .h는 헤더로, 함수의 선언을 저장하고 .lib는 선언된 메서드의 실제 구현을 저장한다.
