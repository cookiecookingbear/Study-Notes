# 프로세스

- 프로그램이 실행되어 메모리(RAM)에 올라가 CPU의 처리를 받고 있는 상태의 실행 인스턴스

### 운영체제가 프로세스를 사용하는 이유

- 여러 프로그램을 사용하는 환경에서, OS가 각 실행 흐름을 구분해서 관리하지 않으면
    1. 서로 다른 프로그램이 메모리를 침범해서 값을 덮어쓰는 문제
    2. 실행된 하나의 프로그램이 CPU를 독점해서 다른 프로그램을 멈춰버리는 문제\
등이 발생한다.

### 운영체제가 프로세스를 사용하는 방법

실행된 프로그램을 프로세스라는 독립된 단위로 쪼개

- 스케줄링을 통해 CPU사용시간
- 독립된 메모리 공간(가상 주소 공간)
- 파일, 네트워크 소켓 같은 **자원(핸들)**

등을 나눠준다.
이런 면에서, 프로세스는 OS가 자원을 나눠주는 단위라고도 표현할 수 있다.

### 프로세스의 생명주기

1. New(생성)
   
    - 프로세스가 막 생성되어 OS에 등록되는 단계

2. Ready(준비)

    - 실행할 준비는 되었지만, CPU순서를 기다리는 상태

3. Running(실행)

    - 실제로 CPU를 할당받아 명령어를 처리 중인 상태

4. Waiting/Blocked(대기)

    - I/O를 기다리는 중(CPU를 사용할 수 없는 상태)

5. Terminated(종료)
    
    - 실행이 끝나고 자원이 회수되는 상태

- 여러 프로세스가 '동시에 실행되고 있는 것처럼'보이는 이유는, 실제로 CPU가 여러 프로세스를 동시에 처리하고 있는게 아니라, 아주 짧은 시간 단위로 프로세스를 번갈아 가며 실행(Running/Ready)하기 때문이다. 이를 **컨텍스트 스위칭**이라고 한다.
- 컨텍스트 스위칭을 하기 위해 각 프로세스의 실행 상태(레지스터 값, PC값 등)를 저장해두는 자료구조가 [PCB, Process Control Block](./PCB_processControlBlock.md)라고 한다.
