# 캐시 메모리 (Cache Memory)

- CPU가 자주 사용하는 데이터를 임시 저장해 두는 매우 빠른 소용량 메모리

### 필요성

- CPU와 RAM의 속도 차이

|장치|접근 시간|
| ------------ | ------------ |
| CPU Register | 1 cycle 수준|
| L1 Cache| 수 cycle|
| L2 Cache| 수십 cycle|
| L3 Cache| 수십-수백 cycle|
| RAM|수백 cycle|
| SSD|수만~수십만 cycle |

- 결과적으로 CPU가 계산하는 시간보다 RAM을 기다리는 시간이 훨씬 많다. (Memory Wall문제)

### 위치

- CPU와 RAM 사이

	> CPU가 RAM을 확인하기 전에 캐시를 먼저 확인한다.

### 전제

- 시간 지역성(Temporal Locality)

	> 최근 사용한 데이터는 곧 다시 사용될 가능성이 높다.

- 공간 지역성(Spatial Locality)
- 
	> 접근한 데이터 근처도 곧 사용할 가능성이 높다.

### 동작 원리

1. CPU가 주소 요청
1. 캐시 확인
1. 캐시에 있으면 캐시의 데이터 활용(Cache Hit)
1. 캐시에 없으면 RAM 접근(Cache Miss)

- 데이터 저장 방식

	- 바이트 단위가 아닌 Cache Line이라는 단위로 저장한다.
	- CPU에서 단일 주소만 요청해도 해당 주소가 저장된 Cache Line의 모든 값을 반환할 수 있다.

- RAM은 보통 DRAM이지만, 캐시의 경우 SRAM이라 RAM보다 빠르다.



### 계층 구조

1. L1 Cache

	- 가장 빠르고, 가장 작다.
	- CPU 코어 내부에 존재한다.

1. L2 Cache

	- L1보다는 크지만, L1보다 느리다.

1. L3 Cache

	- 캐시 메모리 중 가장 크고 느리다.

- 캐시 확인도 L1 - L2 - L3 순서로 하고, 셋다 Miss하면 RAM에 접근한다.

### 캐시 히트율 (Hit Rate)

- 가장 중요한 성능 지표, 높을수록 좋다.

$Hit Rate = \frac{Hit}  {(Hit + Miss)}$
