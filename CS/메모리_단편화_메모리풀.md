# 메모리 풀 (Memory Pool)

- 필요할 때마다 메모리를 새로 할당/해제하지 않고, 미리 일정량의 메모리를 확보해 두고 그 안에서 재사용하는 메모리 관리 기법

- Object Pooling과 매우 밀접

### 기존 방식의 문제점

1. 할당 / 해제 비용

	- 메모리 할당자는 빈 공간을 찾고, 관리 정보를 갱신해야 한다.
	- 해제도 마찬가지로 관리 비용이 발생한다.

1. 메모리 단편화

	- 반복적으로 메모리를 할당 / 해제하면 힙 공간이 조각날 수 있다
	- 이 결과로 외부 단편화가 발생할 수 있다.

1. GC부담 증가

### 구조

- 메모리 풀 안에 미리 메모리 블록을 준비한다.

- 메모리 할당 요청이 있으면, 빈 블록을 할당한다.

- 메모리 해제 요청이 있으면, 해당 블록을 회수하되 운영체제 선까지 회수하지 않고 다시 풀에 넣는다.


### 동작 과정

1. 초기화

	> 프로그램 시작 또는 특정 시점에 메모리를 미리 확보한다.

1. 할당

	> 할당 요청시 Free List에서 사용 가능한 블록 하나를 꺼내 할당한다.

1. 해제

	> 사용이 끝난 블록을 회수하여 다시 Free List에 넣는다.

### 종류

- 고정 크기 메모리 풀

    - 모든 블록의 크기가 같다.
    - 가장 단순하고 자주 쓰이는 형태
    - 할당과 해제가 매우 빠르다
    - 요청 크기보다 블록이 크면 내부 단편화가 발생한다.

- 여러 크기의 메모리 풀

	- 내부 단편화를 줄이기 위해 크기별 풀을 여러개 둔다.
	- 운영체제 커널, 게임 엔진, 고성능 서버에서 자주 사용된다.

### 장점

1. 할당 비용 감소
1. 해제 비용 감소
1. GC 부담 감소
1. 성능 예측 가능성 증가
1. 외부 단편화 감소
	> 고정 크기 블록을 재사용하기 때문에 일반 힙처럼 다양한 크기의 빈 공간이 섞이는 문제가 줄어든다. 특히, 같은 크기의 객체를 반복적으로 생성/삭제하는 경우 효과가 크다.

### 단점

1. 초기 메모리 사용량 증가
1. 풀 크기 관리 필요
1. 객체 상태 초기화 실수
    > 이전 상태가 남을 수 있다.
1. 복잡도 증가
