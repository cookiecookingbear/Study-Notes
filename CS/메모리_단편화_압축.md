# 메모리 압축

- 흩어져 있는 사용 중 메모리 블록들을 한쪽으로 모아서, 큰 연속 빈 공간을 만드는 기법
- 외부 단편화를 해결하기 위한 방법

### 전제조건

- 주소 재배치가 가능해야 함.

	> 사용 중인 메모리 블록을 이동하면 해당 블록의 물리 주소가 바뀌므로, OS에서 해당 프로레스의 주소 변환 정보를 갱신할 수 있어야 한다.

### 진행 과정

1. 사용 중인 메모리 블록 확인
1. 블록들을 한쪽 방향으로 이동
1. 빈 공간을 하나의 영역으로 통합
1. 각 블록의 주소 정보 갱신
1. 프로세스 실행 재개

### 비용

- 이론적으론 명확하나, 실제로는 비용이 크다.

1. 데이터 이동 비용
    
	> 사용 중인 메모리 블록을 실제로 복사해야하기 때문에, 메모리 크기가 클수록 비용이 커진다.

1. 실행 중단 가능성

1. 주소 정보 갱신 비용

	> 세그먼테이션을 사용 중이라면 ,Segment Table의 내용 중 Base를 갱신해야하기 때문에 비용이 든다.\
	> 페이징을 사용 중이었다면, 페이지 단위로 매핑이 가능해서 사실상 압축의 의미가 옅어진다.

1. 포인터 문제

### 기타 

- Compacting GC

	- 일부 가비지 컬렉터는 압축과 비슷한 동작을 통해 힙을 정리하는데, 이런 GC를 Compacting GC라고 한다.
	- 단,  OS단계의 압축과 Compacting GC의 압축은 층위가 다르다.
    	
		> OS : 프로세스, 세그먼트, 메모리 블록\
		> GC : 힙 내부 객체

- Compaction / Compression

	- Compaction

    	> 본문에서 말한 압축과 동일한 내용. 메모리 블록을 이동해서 빈 공간을 합치는 것.\
		> 보통 운영체제 단편화 문맥에서 등장하는 메모리 압축

	- Compression
    	
		> 데이터를 압축 알고리즘으로 줄이는 것.\
		> 단편화 해결보다는 RAM사용량 절감이 목표다.
