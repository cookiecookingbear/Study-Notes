# .dll (Dynamic Link Library)

- 프로그램이 실행되는 동안(런타임)에 동적으로 불러와 사용하는 라이브러리 파일

## .lib와의 차이점

- 실행 시점

	1. .lib은 프로그램 빌드 시점에 이미 .exe에 포함된다.
	2. .dll은 빌드된 프로그램을 실행하고, 프로그램에서 필요시 .dll을 로드한다.

## 사용 목적

- 코드 재사용

	- 여러 프로그램에 같은 내용의 기능이 필요한 경우, .dll파일 하나만 있으면 해결 가능.
    	> 만약 .lib을 사용했다면, .lib을 사용한 프로그램 개수만큼 복사되어 저장공간을 차지했을 것이다.

- 실행 파일 크기 감소

- 업데이트 용이성 증가

	- 기능을 구현한 .dll파일만 수정하면 됨.
    	> 만약 .lib였다면 프로그램 전체를 다시 빌드해서 배포해야함

## 실제 사용

- 유니티에서는 실제로 .dll을 많이 사용한다. 예를 들어 유니티 폴더 내 Assets/Plugins/에 별도로 작성한 MyPlugin.dll파일을 삽입하면 C#스크립트 작성시 `using Myplugin;`을 통해 해당 .dll파일을 사용할 수 있다.

## 장/단점

1. 장점

	1. 코드 공유
    	>하나의 .dll로 여러 프로그램이 공유할 수 있다.
	1. 업데이트 용이
    	>필요시 .dll만 수정하면 업데이트가 가능해진다.
	1. 메모리 절약
    	>공유 가능
	1. .exe크기 감소

2. 단점

	1. 배포가 복잡해짐
    	>.dll을 별도로 배포해야 한다.
	1. 버전 충돌
    	>서로 다른 프로그램이 같은 이름,다른 버전의 .dll을 사용하면 충돌이 날 수 있다. = dll hell
	1. 로딩 실패 가능
    	>링크가 잘못 연결되어 있으면 로드할 수 없다.
	1. 디버깅 어려워짐
    	>외부 모듈이므로 디버깅이 좀더 복잡해진다.

## P/Invoke

- C나 C++에서 사용하는 .dll안의 메서드를 C#에서 호출하는 기술
```csharp
[DllImport(".dll파일명")]
```
으로 사용한다.

- 이때, C/C++의 .dll 안의 호출된 메서드를 사용할 때는
```csharp
private static extern int A();
```
처럼 `extern`키워드를 사용해야 한다. 이는 '이 메서드의 구현은 내가 가지고 있지 않다'는 의미다.

- 보통 필요한 대부분의 기능을 유니티에서 연결을 만들어 놨기 때문에, 실무에서도 거의 쓰이지 않으나, 외부 SDK연동이 필요하거나, 자체 C++라이브러리를 추가하는 등의 특수한 경우에는 P/Invoke를 사용한다.
