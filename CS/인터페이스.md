# 인터페이스 (Interface)

## 무엇을 할 수 있는지만 정의하고, 어떻게 하는지는 정의하지 않는 것.

- **목적**
    1. 다형성 제공

        > 공통된 특징을 묶어 인터페이스 하나로 정의할 수 있으며, 이 인터페이스를 구현하는 클래스들이 어떤 기능을 가져야 하는지 강제할 수 있다.

    1. 결합도 감소

        > 인터페이스를 통해 호출부를 구성하면 호출부는 특정 클래스가 무엇을 하는지 알 필요가 없어진다. 인터페이스를 구현하는 클래스가 어떻게 동작하는지 알 필요 없이 인터페이스에 정의된 메서드만 알면 된다.

    1. 확장성 증가
        > 새로운 클래스나 객체가 추가되어도 코드 수정 없이 추가하기만 하면 된다.

- **C#에서의 인터페이스**
    1. 선언
        ```csharp
        public interface IDamageable
        {
           void TakeDamage(int damage);
        }
        ```
    1. 구현
        ```csharp
        public class Player : IDamageable
        {
           public void TakeDamage(int damage)
           {
              hp -= damage;
           }
        }
        ```
    1. 사용
        ```csharp
        IDamageable target = player;
        target.TakeDamage(10);
        ```
    1. 특징
        - 인터페이스 내부에는 기본적으로 메서드 선언만 존재한다.
        - 클래스는 하나만 상속받을 수 있지만, 인터페이스는 다중 상속이 가능하다.
    1. C++과의 차이점
        - C++에서는 `interface`키워드가 없다. 대신 순수 가상 함수를 사용한다.
            ```cpp
            class IDamageable
            {
            public:
                virtual void TakeDamage(int damage) = 0; // 순수 가상 함수
            };
            ```
        - 이와 같이 `interface`키워드가 없는 이유는, C++설계상 클래스, 상속, 가상 함수만으로도 인터페이스를 표현할 수 있게 설계되어 있기 때문.

- **장점**

    1. 다형성
    1. 결합도 감소
    1. 확장성 증가
    1. 테스트 용이
    1. 다중 구현 가능

- **단점**

    1. 구조 복잡화
    1. 추적이 어려워짐
    1. 과도한 추상화 위험
